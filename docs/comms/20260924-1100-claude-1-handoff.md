## Release decision

**Release acceptance passed.** `B-REL-002` is resolved and no blocker or major defect remains open.
The default 2D North Star now uses a compass rose with E highlighted, a Sun on the eastern horizon,
and a rising arc leading toward East. Live React Flow bounds confirm that nodes do not touch or
overlap, and the directed edges do not run beneath cards.

The review found two other open defects, and both were fixed in this ticket:

- `B-QA-001` (major): golden coverage was 11/15. It is now **15/15**.
- The 2D flow edges had no arrowheads and too little contrast (a major accessibility and pedagogy
  defect, D-005). They now have arrowheads and a 7:1 stroke.

Release can proceed. The remaining items are one minor bug (`B-REL-001`) and two non-blocking
verification gaps: hardware FPS, and an LLM-backed pedagogy sample.

## What changed

- **Parser (offline rules, D-005).**
  - A state-change chain with a curated water-cycle closure.
  - Inputs → outputs ("uses … to make …") that never turns energy into matter.
  - A process node plus an adjective condition for "melts into … when it gets warm".
  - Motion verbs in subject–verb–object sentences now emit `moves`.
  - Curated ≤ 25-word summaries for every golden entity, and a grammatical generic template.
  - SG notes for P-008 (clouds), P-009 (mass comes from CO₂) and P-012 (melting).
- **2D canvas.**
  - `arrow` and `path` edges end in a closed arrowhead; bearing, leader and containment lines stay
    plain.
  - All edges use `ui.textMuted` at 2 px.
  - Animated edges are solid, because dashes mean "optional".
  - OSG centre coordinates now project through deterministic rendered pixel footprints, followed by
    a collision pass; presentation mode preserves those dimensions.
  - The compass scene renders its registered compass/Sun/rise SVG primitives. E is labelled and
    emphasized without relying on colour, and the Sun crosses a visible eastern horizon.
- **Compass layout (D-006).** Bearing resolution follows relation chains, placing Sun → Rise → East
  in causal order along the east side while keeping the rise arc above the horizon.
- **Documentation.**
  - §14.3 score record and the offline parser scope in `docs/PEDAGOGY.md`.
  - D-005 in `docs/DECISIONS.md`.
  - Milestone status in `PLAN.md`.
  - Resolution notes on `B-QA-001` and `B-QA-002`, and the new minor bug `B-REL-001`.

## Implemented behaviour (release summary)

- Utterance → SG → VP → positioned OSG through `/v1/visualize`, with SSE progress, Zod validation
  at every boundary, caching, rate limiting, and a 500-character limit.
- Rule-first metaphor selection (§10.1), and deterministic layouts for every metaphor, with no
  node or label overlap in the assembled or exploded state.
- The 2D icon canvas opens by default. 3D is used only for curator-approved scenes (D-004); the
  sandwich opens in 3D, while sun/east opens in its verified 2D compass presentation.
- Explode/assemble, click → summary → explanation, drill-down with breadcrumbs, audience
  selector, "Did you know?" chips, an "unsure" indicator for low confidence, keyboard shortcuts,
  a "Diagram as list" outline, a colour-blind-safe palette, and reduced motion.
- Canvas editing with 100-step undo, save, read-only share links, and PNG/SVG/GLB/JSON export.
- Deterministic presentation playback with edit locking.
- A secure CLI harness as an `LLMClient` backend. Every stage falls back to byte-identical
  offline output when no provider is configured or a call fails.

## Safe local harness configuration

No credentials are needed. Without any `OPSIS_LLM_*` variables, Opsis runs fully offline on the
deterministic rules. To use a local CLI instead of an HTTP key:

```sh
OPSIS_LLM_PROVIDER=harness:claude   # or harness:codex / harness:agy
OPSIS_LLM_MODEL=<model id>          # required; must match ^[A-Za-z0-9][A-Za-z0-9._:/-]{0,63}$
OPSIS_HARNESS_BIN=<absolute path>   # must be on the allowlist in apps/api/src/harness/index.ts
OPSIS_HARNESS_TIMEOUT_MS=30000      # optional, 100–300000
corepack pnpm --filter api dev      # binds 127.0.0.1:8000
```

- Sign in with the CLI's own login flow first. Opsis never reads, copies or logs CLI credential or
  config files, and it does not use an API key in harness mode.
- The child process runs:
  - with `shell: false`;
  - in an empty temporary `cwd`;
  - with an allowlisted environment (all `OPSIS_*` variables removed);
  - with the prompt on stdin only;
  - with time, output-size and concurrency caps (at most 2 processes).
- Stderr never reaches clients.
- Any configuration or version problem fails closed to offline mode with a startup warning.
- Keep `HOST` on loopback, and never put keys in the repository or in shared `.env` files.
  `OPSIS_LLM_API_KEY` is only for HTTP providers.

## Known limitations

- The executable allowlist in `apps/api/src/harness/index.ts` holds audited absolute paths from
  one development machine. On any other machine, harness mode fails closed to offline until the
  paths are re-audited. The allowlist also records a local username, so consider making it
  configurable.
- The 50-node 60/30 fps budget has not been measured on real hardware. The gate skips under
  software rendering.
- The offline `whyItMattersHere` is a grounded template, so relevance is the lowest pedagogy
  dimension (4.15). The offline path also uses one summary for every audience. LLM explanations
  were not sampled.
- The offline parser covers only the documented patterns. Other sentences fall back to a
  `labeled_card` diagram with an ambiguity note.
- `B-REL-001` (minor): cycle edges cross on the return half; the minimap is empty and the zoom
  controls have no icons in the baselines; node cards show the raw primitive id.
- `PUT /v1/osg/:id` is unauthenticated (MVP, no accounts; see `apps/api/README.md`).
- `bowl`, `cell` and `hand` still have no 2D icon (D-004).

## Non-goals (PROMPT.md §18, unchanged)

classroom dashboards, and native mobile apps.
